# Свадебное приглашение «Звёздная карта»

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind 3 · Motion 13 · ExcelJS

Одностраничное приглашение с формой ответа гостя и админкой. Дизайн — «глубокий космос»:
закреплённый фон с Млечным Путём, карта неба с созвездиями, анимации на Motion.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # и задайте свой пароль
npm run dev                  # http://localhost:3000, админка — /admin
```

`.env.local`:

```
ADMIN_TOKEN=придумайте-длинный-пароль
# необязательно: база данных (иначе ответы пишутся в data/rsvp.json)
# DATABASE_URL=postgresql://...
```

Без `ADMIN_TOKEN` админка закрыта (ответ 503) — пароля «по умолчанию» больше нет.

## Где хранятся ответы

| Условие | Хранилище |
|---|---|
| Задан `DATABASE_URL` (или `POSTGRES_URL`) | PostgreSQL — `lib/storage-postgres.ts`. Таблица `rsvp_entries` создаётся сама при первом запросе (схема — `db/schema.sql`) |
| Локально без базы | Файл `data/rsvp.json` — `lib/storage-file.ts` |
| Локально задан `RSVP_DATA_FILE` | Файл (так работают тесты и e2e — чтобы не писать в боевую базу) |
| Vercel без базы | Ошибка с подсказкой в админке. Файловая система Vercel временная — ответы бы терялись |

Выбор делает `resolveStorageConfig()` в `lib/storage.ts`; API-маршруты работают через общий интерфейс `Storage`.

## Где что менять

| Что | Где |
|-----|-----|
| Имена, дата, время, место | `lib/wedding.ts` |
| Фото пары | `public/photo.webp` (кадр подобран так, что оба лица целиком в круге), путь — `WEDDING.photoSrc` |
| Фото дома | `public/house.webp`; рамка повторяет пропорции снимка (`housePhotoWidth/Height` в `lib/wedding.ts`), поэтому дом виден целиком |
| Адрес и ссылка на карту | `WEDDING.address` в `lib/wedding.ts` (ссылка на Яндекс Карты строится сама) |
| Цвета, шрифты, размеры | `app/tokens.css` (primitive → semantic → component) |
| Список напитков и лимиты полей | `lib/constants.ts` |
| Фон Млечного Пути | `public/sky/milky-way-*.webp` (вертикальный — телефоны, горизонтальный — компьютеры) |

## Тесты

```bash
npm run typecheck       # TypeScript
npm test                # Vitest: логика, API, компоненты
npx playwright install chromium   # один раз
npm run test:e2e        # Playwright: 36 тестов на production-сборке
npm run check           # typecheck + unit + build
# Проверка Postgres-хранилища на настоящей базе (отдельная тестовая база! схемы test_* пересоздаются):
TEST_DATABASE_URL=postgres://postgres@127.0.0.1:5432/rsvp_test npm run test:db
```

Без `TEST_DATABASE_URL` тесты Postgres пропускаются (skipped), остальные идут как обычно.

Что проверяют e2e (подробно — `tests/TEST_PLAN.md`): адаптив на 11 ширинах от 280 до 1920 px
(нет горизонтальной прокрутки, имена и карта не выходят за экран), цели касания ≥ 44 px,
анимации и режим «уменьшить движение», сценарий гостя, админка и выгрузка Excel,
доступность (axe), отсутствие ошибок в консоли.

## Админка

`/admin` → пароль из `ADMIN_TOKEN`. Статистика, поиск, удаление, выгрузка в Excel
(всё / список гостей / напитки / выбранные). В форме гостя два поля: имя и напитки. Пароль передаётся только в заголовке `x-admin-token`.

## Деплой на Vercel (бесплатно: Vercel Hobby + Neon Free)

На Vercel код работает в serverless-функциях: файлы, записанные во время работы, не сохраняются.
Поэтому ответы хранятся в Postgres от Neon, который подключается к проекту из Vercel Marketplace.

1. **Залейте проект на GitHub.** `node_modules`, `.next`, `.env*.local` и `data/` в git не попадают (см. `.gitignore`).
2. **Создайте проект на Vercel:** vercel.com → Add New → Project → Import (ваш репозиторий).
   Фреймворк Next.js определится сам. В Environment Variables добавьте `ADMIN_TOKEN` — длинный пароль. Нажмите Deploy.
3. **Подключите базу:** вкладка проекта Storage → Create Database → Neon → план Free.
   Регион выберите рядом с регионом функций: по умолчанию функции Vercel работают в Washington, D.C. (`iad1`),
   ему соответствует AWS US East. Если меняете регион функций (Settings → Functions), выберите для базы тот же.
4. **Привяжите базу к проекту:** Connect Project → отметьте Production (и Preview/Development при желании) → Connect.
   Интеграция сама добавит `DATABASE_URL` и другие переменные.
5. **Сделайте Redeploy** (Deployments → ⋯ → Redeploy): новые переменные окружения действуют только в новых деплоях.
6. **Проверьте:** отправьте форму на сайте → откройте `/admin` → ответ на месте → удалите его.
   Таблицу можно посмотреть и в самом Vercel: Storage → база → вкладка с данными, или Open in Neon.

Ничего запускать вручную не нужно: таблица создастся при первом ответе или первом входе в админку.

Если что-то не так — `/admin` покажет причину (нет `ADMIN_TOKEN`, не подключена база). Подробности ошибок базы — в Logs проекта на Vercel.

Локальная разработка с той же базой: `npx vercel link`, затем `npx vercel env pull .env.local`, затем `npm run dev`.
Осторожно: это боевые данные — удаление в локальной админке удалит их и на сайте.

### Ограничения бесплатных тарифов

- **Vercel Hobby** — только для личных некоммерческих проектов. Для сайтов клиентов нужен Pro.
- **Neon Free** — 0,5 ГБ на проект и 100 CU-часов вычислений в месяц; база «засыпает» после 5 минут без запросов,
  поэтому первый запрос после паузы дольше обычного. Страница приглашения статическая и базу не будит —
  её используют только отправка формы и админка.

### Доступ из России

Доступ к Vercel из российских сетей нестабилен и зависит от провайдера. Обязательно проверьте сайт без VPN
с нескольких сетей (домашний интернет, разные мобильные операторы) до рассылки приглашений.
Запасной вариант — любой обычный сервер (VPS): `npm run build && npm start` работает и с файлом `data/rsvp.json`, и с Postgres.

Каллиграфические шрифты (Great Vibes — имена и заголовки, Bad Script — остальной текст) подключены локально, лицензия SIL OFL — `app/fonts/`.

## Созвездия на карте неба

Слева от фото — Водолей, справа — Телец (с Плеядами). Это настоящие звёзды: координаты (J2000),
звёздные величины и линии фигур взяты из каталога [d3-celestial](https://github.com/ofrohn/d3-celestial)
(© 2015 Olaf Frohn, лицензия BSD-3-Clause). Данные и раскладка — `components/chart/constellations.ts`,
проверки формы и положения — `tests/unit/constellations.test.ts`.

## Анимации и надёжность

- Обычный режим: появление первого экрана на Motion (имена из размытия, карта неба, созвездия, тексты), космос с вращением неба и падающими звёздами.
- Системная настройка «Уменьшить движение»: мягкое проявление по прозрачности, без сдвигов, размытия и вращения; фон неподвижен.
- Без JavaScript (встроенные просмотрщики файлов, строгие настройки браузера): всё видно сразу — `<noscript>` в `app/layout.tsx`.
- Если скрипты не загрузились или упали: через 3,5 с контент проявится сам — CSS-страховка в конце `app/globals.css`.
